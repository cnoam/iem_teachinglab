# provision_VM_ssh

Provisions one Azure VM per student group and pushes each group's SSH deploy
key onto its VM. Terraform creates the infrastructure; Ansible configures the
VMs and installs the keys.

- **Input:** `users.csv` (one row per group, columns = member emails) drives the
  group list. Group `N` becomes team `group_NN` (zero-padded) — see `main.tf`.
- **VM naming:** `<name_prefix>-group_NN` in resource group `<name_prefix>-group_NN`
  (`name_prefix` defaults to `course`).
- **Key files:** `keys/group_NN.pub`, one per group, consumed by
  `playbooks/deploy-keys.yml`.

## VM power state — important

`terraform apply` creates the VMs **powered on**. Two independent mechanisms
deallocate them *later*:

1. **Daily auto-shutdown** (`azurerm_dev_test_global_vm_shutdown_schedule`,
   `main.tf`) — deallocates at `auto_shutdown_time` (default `2350` UTC) every day.
2. **Idle-watcher** (systemd timer from `cloud-init.yaml`) — deallocates after
   **4 hours** of 15-min load average below 0.20.

Ansible can only reach a **running** VM. So run the playbooks in the window right
after `terraform apply` (at least ~4 h, until the daily shutdown). If a VM has
since been deallocated, start it first:

```bash
# one group (adjust to your name_prefix):
az vm start --name course-group_01 --resource-group course-group_01

# or every deallocated lab VM at once:
az vm start --ids $(az vm list -d --query "[?powerState=='VM deallocated'].id" -o tsv)
```

After a fresh start the idle-watcher's 4-hour clock resets from boot, so you
again have a comfortable window.

## Collecting & installing group keys

Students submit one SSH **public** key per group via a shared sheet, exported to
CSV (group id like `group01` in column A, the `ssh-...` key in column B).

```bash
# 1. Parse the submitted CSV -> keys/group_NN.pub  (normalizes group01 -> group_01)
python3 scripts/parse_student_keys.py [path/to/keys.csv]

# 2. Make sure the target VM(s) are running (see "VM power state" above)

# 3. Install the key into the deploy user's authorized_keys (exclusive)
ansible-playbook -l group_01 playbooks/deploy-keys.yml
```

`deploy-keys.yml` uses `exclusive: true`, so it **replaces** the deploy user's
`authorized_keys` — this is also how you rotate or revoke:

- **Rotate:** replace `keys/group_NN.pub` and re-run.
- **Revoke:** replace `keys/group_NN.pub` with an empty file and re-run.

Limit with `-l` to the groups you actually have keys for. Running against the
whole inventory fails on any group whose `keys/group_NN.pub` is missing, because
the playbook does `lookup('file', ...)`. Pass several with `-l 'group_01:group_02'`.

Typical recurring workflow: **new keys arrive → start the relevant VMs if needed
→ run the parser → run `deploy-keys.yml -l <those groups>`.**

## Full provisioning sequence

```bash
terraform apply                                        # VMs created, powered ON
ansible-playbook -l group_01 playbooks/base_setup.yml  # apt + Docker
ansible-playbook -l group_01 playbooks/deploy-keys.yml # install student key
```

## Files

| Path | Purpose |
| --- | --- |
| `main.tf`, `variables.tf`, `outputs.tf` | VM, network, RBAC, auto-shutdown |
| `cloud-init.yaml` | first-boot setup: deploy user, Docker, SSH hardening, idle-watcher |
| `inventory.ini` | generated by Terraform; one host per group |
| `playbooks/base_setup.yml` | apt update + Docker |
| `playbooks/deploy-keys.yml` | install/rotate/revoke each group's deploy key |
| `scripts/parse_student_keys.py` | CSV of submitted keys → `keys/group_NN.pub` |
| `keys/group_NN.pub` | per-group public deploy keys |
